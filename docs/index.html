這座 wiki 怎麼運作

資料分兩層：raw/ 是人放進來、不會被改的原始來源（論文摘要）；wiki/ 是 AI 讀完 raw 後整理出來、會持續修改與互相連結的知識頁。網站由 scripts/build.py 從 wiki/ 產生。每個主張都連到「來源」頁，來源頁再對應到 raw/ 的原始檔。

建議閱讀順序

  3. RAG 怎麼評估：怎麼知道自己的 RAG 做得好不好。

概念

概念Graph RAG

把文件抽成實體與關係的知識圖，檢索時在圖上走、聚合社群摘要，回答向量 RAG 答不了的全局與多跳問題。

概念RAG 怎麼評估

把評估拆成「檢索找得準不準」和「生成忠不忠實」兩段看，用 LLM 當評審可以不靠人工標準答案。

概念什麼是 RAG

檢索增強生成：生成答案前先從外部知識庫找資料，把找到的片段和問題一起給模型。
