# RAG 是什麼？
## 從向量 RAG 到 Graph RAG

給完全沒接觸過的人的 12 頁入門。內容全部來自 [[index|RAG Wiki]]，每頁右下角標示出處。

## 先講問題：語言模型哪裡不夠用？

大型語言模型（LLM）的知識鎖在參數裡，所以：

- **會幻覺**：講得很順，但內容是編的。
- **有截止日期**：訓練之後發生的事它不知道。
- 看不到**公司內部的資料**：你自己領域的文件，它沒讀過。
- **追不到出處**：答案對不對，你沒辦法回頭查。

有沒有不動模型、直接補知識的方法？

來源: rag
## 解法：讓模型先查資料再回答

檢索增強生成（Retrieval-Augmented Generation, RAG）：

> 回答之前，先從外部資料庫**檢索**相關文件，再把文件和問題一起放進提示（prompt），讓模型**有依據地生成**。

知識搬到模型外面的索引，換資料就等於更新知識，而且答案可以附引用。

來源: rag
## RAG 的三個步驟

1. **索引（Indexing）**：把文件切成片段，每段用嵌入模型轉成向量，存進向量資料庫。
2. **檢索（Retrieval）**：使用者的問題也轉成向量，找出最相似的前幾個片段。
3. **生成（Generation）**：把片段和問題組成 prompt 給模型，產生答案。

這就是最基本的 **Naive RAG**。

來源: lewis-2020-rag
## 「RAG」這個詞從哪來？

2020 年 Lewis 等人的論文第一次提出 RAG：

- 把**參數記憶**（預訓練的生成模型）和**非參數記憶**（維基百科的向量索引）接在一起。
- 檢索器用 DPR，生成器用 BART，兩者一起微調。
- 開放域問答上贏過只靠參數的模型，生成的內容更具體、更少幻覺。

今天工程上說的 RAG 多半不訓練模型、只靠 prompt 組合（見 [[rag]]），但核心想法一樣：知識放外面，**換索引就更新**。

## RAG 不只一種：三個範式

| 範式 | 做法 |
|---|---|
| **Naive RAG** | 切塊、嵌入、檢索前幾段、塞進 prompt |
| **Advanced RAG** | 檢索前改寫問題、檢索後重排與壓縮 |
| **Modular RAG** | 搜尋、路由、記憶等做成模組，可以重組 |

大多數系統從 Naive 開始，碰到問題再往 Advanced 走。

## 向量 RAG 的兩個盲點

向量檢索只比對「局部相似」，所以有兩類問題答不好：

- **全局問題**：「這批文件主要在講什麼？」沒有任何一個片段能回答，取前幾段沒有意義。
- **多跳問題**：「A 的老闆創辦的公司總部在哪？」要跨文件串起中間節點，一次相似度檢索抓不到。

要解這兩類問題，需要把「片段」升級成「圖」。

來源: graph-rag
## Graph RAG：把知識整理成圖

Graph RAG 泛指把知識整理成**圖**：節點是實體或概念，邊是關係。檢索時沿著圖找相關節點與摘要，而不只比對向量。

好處：

- 全局問題可以靠「社群摘要」回答。
- 多跳問題可以沿著邊走過去。

---
來源: graph-rag
## 微軟 GraphRAG 怎麼做

1. **抽取**：用 LLM 從每個片段抽出實體、關係與描述，合併成知識圖。
2. **社群與摘要**：把關係緊密的實體分群，為每個社群預先寫摘要。
3. **全局查詢**：每個社群摘要先各自回答一部分，再彙整成最終答案。
4. **局部查詢**：從問題抽出實體，找到圖上的節點，拉鄰居與相關片段。

代價：建圖要對整批文本跑很多次 LLM，貴而慢。

---
來源: guo-2024-lightrag
## LightRAG：省成本的 Graph RAG

- 圖與向量**一起用**：實體與關係建成圖，節點和邊也做成向量。
- **雙層檢索**：低層找具體實體與關係，高層找主題與抽象概念。
- **增量更新**：新文件只合併新圖，不必整張重建。

目標是比微軟 GraphRAG 便宜、快，又保留圖的好處。

## 怎麼知道自己的 RAG 做得好？

RAG 是兩段接起來的，要分開評：

| 維度 | 問的問題 | 壞掉代表 |
|---|---|---|
| 上下文相關性 | 檢索到的段落真的跟問題有關嗎？ | 檢索有問題 |
| 忠實度 | 答案裡每個主張在上下文找得到依據嗎？ | 模型在幻覺 |
| 答案相關性 | 答案有沒有回到問題？ | 答非所問 |

RAGAS 用 LLM 當評審算這三個分數，不需要人工寫標準答案。

## 總結與延伸閱讀

- RAG：讓模型先查再答，知識放外面、可更新、可引用。
- 向量 RAG 答不好全局與多跳問題，Graph RAG 用知識圖補上。
- 評估要拆開看檢索與生成。
